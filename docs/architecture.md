# Architecture

The installable application is in `src/desktranslate`. Qt owns presentation; domain types have no Qt dependency. `models.py` defines capture, OCR and translation protocols. Settings and dependencies are injected at boundaries.

```
Capture → thumbnail change gate → latest frame mailbox (capacity 1)
  → isolated OCR process → reconstruction / stabilization
  → latest text mailbox (capacity 1) → pooled provider HTTP
  → bounded events → Qt timer → overlay
```

A session has a serial and frame generation. Static-frame changes invalidate prior work immediately. Continuously moving backgrounds are sampled at a bounded interval; confirmed source-text changes and blanks advance the semantic generation, so changing pixels do not starve OCR or discard every translation. Pause, stop, configuration and capture-geometry changes invalidate work immediately. Results retain their stamp and are checked in workers and presentation. Context receives only accepted results, is bounded by entries, Unicode characters and a conservative UTF-8 byte upper bound for tokens, and is cleared each session. Full request identity is hashed for the bounded memory cache.

`TemporalTextTracker` retains at most six observations for2.5seconds, with text, confidence, capture time and geometry. High-confidence complete subtitles can be proposed immediately. Progressive prefix growth waits for final punctuation or a short quiet period; close character/spacing changes require confirmation. It selects observed strings and does not synthesize character guesses. Delivery is provisional: pixel changes rebase proposals from the last source actually delivered without destroying recent recognition evidence. Draining an event queue alone does not acknowledge presentation. Explicit progressive revision ownership replaces the provisional dialogue turn in context and the opt-in transcript. Blank observations and context/target resets permit the same line to appear again. Stamped physical regions accompany work through delivery so overlay avoidance follows the pixels that produced it.

The isolated process contains native OCR crashes. A recognition worker can replace a failed native process at most twice per minute; it terminates, joins, kills if necessary and closes the process handle before replacement. Pause/failure/stop transitions are atomic. Control generations revoke in-flight capture/inference across pause, stop, context clearing and target changes. An obsolete visual generation may supply temporal evidence within the same control generation, but cannot queue translation or presentation. Two global OCR slots and two provider slots bound overlapping retired pipelines; setup has one separately owned task per UI controller. Moving frames are sampled at bounded quality-specific intervals rather than waiting1.5seconds for the first sample; both pending work mailboxes still hold one item.

`ContextEngine` composes three deliberately separate services: bounded ephemeral dialogue, approved terminology and explicit story notes. Translation caching remains separate. Glossaries are bound to a language pair, with at most1,000 entries/50KB total; local retrieval includes at most24 relevant terms/1,800 serialized bytes from the current line and two recent sources. Latin word boundaries prevent a term such as `cat` matching `cathedral`. CJK terms may occur within unspaced text. Explicit speaker labels are recognized only when the label matches an approved term. Conventional providers receive no story/recent/glossary payload; only exact case-sensitive whole-term translations may bypass them locally. There is no blind substring substitution, learned persistent vocabulary, vector database or automatic cloud fallback.

An idle OCR process can be cancelled during pause. If its cancellation is first consumed by the initial resumed frame, worker retirement requests fresh capture/stabilization; otherwise static content would have no replacement work. Intentional cancellation does not consume crash-recovery allowance. This path has both a deterministic regression and an offscreen real-OCR/HTTP/controller reproduction.

Each HTTP provider keeps the synchronous domain protocol and owns an asyncio loop inside its existing worker. HTTPX AsyncClient reuses connections; `asyncio.wait_for` bounds the complete request, including DNS/connect, response headers and body. Stop schedules cancellation safely into that loop. Bodies and decompression are capped at 8 MB before expansion/allocation, malformed/deep JSON becomes a typed failure, redirects are rejected and rate-limit retry is bounded/cancellable. The Qt loop never runs network awaits or joins workers. Shutdown keeps Qt responsive while a background coordinator waits within a 35-second cleanup budget. There are no unbounded work queues.

Qt logical coordinates are transformed relative to each monitor origin and its physical dimensions. Device names match Win32 monitors to Qt screens. Regions stay within one monitor because a mixed-DPI boundary has no single affine transform. Topology changes invalidate saved regions.

Unproven monitor mapping fails closed rather than multiplying an absolute origin by DPR. `window_capture.py` owns Win32 enumeration, client geometry and a conservative visible-screen compatibility backend. Normalized crops follow move/resize; occlusion/minimize/identity changes are checked on both sides of MSS capture. Optional restart following requires a unique executable-path-hash/title match. Pipeline target movement/rebinding clears context and invalidates generations. Protected/exclusive-fullscreen capture and Windows Graphics Capture are unqualified.

Original RGB is the default OCR input; contrast and subtitle upscaling are explicit alternatives. Structured OCR retains boxes, confidence, language and ordering. Horizontal reconstruction groups rows; experimental vertical ordering reads right-to-left columns.

Claude uses native Messages, Gemini uses generateContent, and Ollama uses /api/chat. Native OpenAI defaults to stateless Responses with storage/streaming disabled and offers explicit Chat Completions compatibility. Existing beta1 OpenAI settings retain Chat mode through migration. OpenAI-compatible servers retain Chat Completions. Model lists are fetched dynamically and known non-text families are removed; unknown capabilities are unverified. OpenRouter price/context metadata is shown only when supplied. JSON source/context data is under a translate-only instruction; there is no general chat UI or tool use.

Credentials are bound to provider and endpoint identity in the OS vault. Remote services require verified HTTPS; HTTP is loopback-only. No redirects or insecure TLS overrides. Logs use a metadata allowlist and discard messages, args, traceback, URLs, headers and dialogue. Diagnostics have a separate allowlist.

Installed builds keep models, settings and logs in OS application data. The portable ZIP's adjacent `portable-mode` marker selects `DeskTranslateData` beside the executable instead. Assets resolve from the package. `DESKTRANSLATE_DATA_DIR` isolates test data; it never holds credentials. Build and test folders are ignored by Git.

`instance.py` owns one application writer per resolved data directory before logging/settings open. Relaunch sends only a fixed activation request over a user-restricted local channel. Separate portable folders remain independent. Four peers,16-byte reads and a2-second idle deadline bound the channel; it accepts no capture commands, URLs, paths or content. A closing owner declines activation and keeps its lock until cleanup finishes. Verification modes force offscreen Qt and never activate another window.

Lifetime ownership uses [QLockFile](https://doc.qt.io/qt-6.12/qlockfile.html) with age-based expiry disabled; Qt can recover a dead owner. Never forcibly remove a live lock. [QLocalServer UserAccessOption](https://doc.qt.io/qt-6.12/qlocalserver.html) restricts the Windows pipe to the current user. Local writable storage is the supported configuration; network/virtual-filesystem locking and moved crash leftovers have separate platform limitations. Tests cover actual owned-process activation/crash recovery, fragmented/invalid messages, idle peers, failed startup and repeated handle/thread cleanup.

Pure `profiles.py`, `shortcuts.py`, `transcript.py`, `diagnostics.py` and `metrics.py` own validation, bounds and data contracts. Dedicated UI modules own profile CRUD/exchange, glossary exchange, onboarding, transcript and support previews. MainWindow coordinates session/capture state; it remains a substantial controller rather than disguising a mechanical rewrite as a completed architecture migration. Imported profiles never establish capture consent. Session transcript memory is opt-in and clears at boundaries. Metrics retain bounded numeric samples, never content.

`presentation.py` maps session state to human-readable status and available actions without Qt. The controller applies the same pause/resume/retry semantics to window, overlay and tray. Persistent capture status is separate from temporary feedback. Event polling runs only while an active session, undelivered receipt or retiring worker requires it; paused sessions poll more slowly, and stopped/completed sessions stop polling after cleanup.

A native cleanup failure overrides apparent one-shot success and recoverable provider errors. The controller stops further capture/work, preserves a restart-required state and rejects new translation sessions. It does not attempt native reaping on the UI thread. Quit rejects late first-run callbacks and new background jobs before coordinating existing workers.

Missing-pack continuation is an ephemeral request, guarded by command identity and settings revision. Clicking Install explicitly authorizes downloading and continuing that request. Stop/cancel/settings changes invalidate it; an old download cannot restart capture or erase a newer request. Setup reuses the provider editor and retains its draft languages instead of creating another credential/model implementation. Reopening setup respects the configured provider, and any provider change invalidates prior sample qualification.

`desktranslate.__version__` is the single version source for package, UI, PE metadata, installer and asset names. `tools/release_support.py` enforces tag/manual/soak/signing gates. Build/runtime inventories are separate, provenance identifies commit and source digest, and public metadata contains no absolute build paths. Stable builds fail if qualification/signing is absent.

Subtitle rendering uses Qt Unicode shaping and cached glyph pixmaps per content/style/size/DPI change. Outlines and shadows reuse cached glyphs. Long text shrinks within a bounded range and clips at an explicit line limit. Edit mode restores interaction and pauses capture. A one-second blank-text grace prevents immediate flicker. The document angle classifier is disabled because it rotated upright Korean subtitles incorrectly.

Model downloads and release discovery use worker-owned async loops with total header/body deadlines and Event-driven cancellation. Identity-only bounded raw chunks prevent decompression expansion in these binary/metadata paths. Provider JSON and release catalogs reject non-finite constants and nesting beyond 64 levels before parsing.

Windows OCR IPC transfers a pipe directly into the spawned child's handle table. This avoids a parent-owned duplicate if cancellation kills the child before unpickling. A kill-on-close job is assigned before the initialization handshake allows native/external engines to start. The OCR worker owns process reaping; cancellation remains nonblocking. The spawn API use is covered by actual Windows handle-growth and descendant-lifecycle regressions on the pinned runtime.

Native display changes invalidate capture immediately and trigger a coalesced100ms overlay refit after the DPI resize cascade. The retained last translation is labelled STOPPED; a fresh region selection is required. ONNX Runtime is opted out at process initialization and before sessions; upstream Windows ETW initialization is described in the privacy policy.
